# 0012 — Zod for validation and shared types

- Status: accepted
- Date: 2026-09-23

## Context

09, sections 2 and 3: every message between server, daemon and UI, and every MCP tool input and output, is defined once as a schema that validates at runtime and gives the TypeScript type. External inputs are all validated (CLAUDE.md).

## Decision

- Zod 4. Schemas live in `packages/protocol`; each schema and its inferred type share one name (`HealthResponse`).
- The server also validates its environment variables with Zod (`apps/server/src/config.ts`). Error messages name the variable and never print its value.

## Alternatives considered

- TypeBox or JSON Schema: native to Fastify, but types are less readable and less known to agents.
- Valibot: smaller bundles, but a smaller ecosystem.

## Consequences

- One dependency for types and validation in every app; the UI bundle includes Zod.
