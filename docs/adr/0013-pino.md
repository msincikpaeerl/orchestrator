# 0013 — Pino for logs

- Status: accepted
- Date: 2026-09-23

## Context

09, sections 3 and 8: structured JSON logs, readable with `docker logs`, with the run id, ticket number and machine in related lines.

## Decision

- Pino, JSON on standard output, level from `LOG_LEVEL` (default `info`).
- One logger per process, created at start and shared with Fastify, so request logs and application logs have the same format.
- Context is added with child loggers (`logger.child({ runId })`), not by formatting strings.
- Configuration values are never logged: `DATABASE_URL` and `ORCHESTRATOR_SECRET_KEY` hold secrets.

## Alternatives considered

- Winston: slower, more configuration, not Fastify's native logger.
- `console`: no levels or structure.

## Consequences

- Logs are JSON in development too; `pino-pretty` can be piped in by hand if wanted.
