## Dependencies between packages

```
apps/server  ──► packages/protocol, packages/db, apps/web (its built dist/), apps/daemon (its built dist/), templates, agents
apps/daemon  ──► packages/protocol (bundled)
apps/web     ──► packages/protocol
```

The daemon's libraries are bundled into its package (ADR 0026), so they are `devDependencies` of `apps/daemon`.

## Server start

`src/main.ts` reads the configuration (`src/config.ts`, Zod), creates the Pino logger, then `startServer` (`src/server.ts`) applies migrations, seeds the default agent profiles from `agents/` (`src/agents/seed.ts`), fails project setups interrupted by a restart, marks machines left `online` offline (no daemon is connected yet), and listens. Routes are declared in `buildApp` (`src/app.ts`), which tests call without a network port. `SIGTERM` closes the HTTP server, then the database pool (made by `createPool`; `endPool` waits until every connection is closed). A lost database connection (a PostgreSQL restart, an administrator's command) is logged as "database connection lost" and replaced by a new one at the next query, whether it was idle, checked out or running a query (`reportConnectionErrors`); it never stops the server.

| `src/projects/setup.ts` | `ProjectSetupRunner` runs a project's setup in the background after it is saved: `repository`, `skeleton`, `branch_protection` for a new repository, `harness` for a linked one. Each step records its result and an event before the next starts, so **Try again** resumes from the failed step. A failure stores the reason written for the owner. The server waits for running setups before closing; at start, `failInterruptedSetups` turns a setup left `in_progress` into `failed` ("interrupted by a restart"). If the answer to the repository creation was lost, trying again reuses the repository found under that name only when GitHub created it after the request (`repo_requested_at`, with the `githubClockToleranceSeconds` tolerance) and it holds at most GitHub's first commit; otherwise "Repository name already taken" (ADR 0023). |
| `src/tickets/` | Tickets: routes (`routes.ts`), the API view of rows and the board order (`model.ts`), and the transition module (`transitions.ts`). "Blocked" is computed when read (a dependency not `done`). |
| `src/tickets/transitions.ts` | The only code that writes `tickets.status` (04, section 2): owner creation in `todo`, **Cancel**, **Mark as done manually** (its mandatory comment written as a `status_change` comment) and **Reopen**; any other action from a state is refused with an explanation. The status, its `ticket.status_changed` event and the comment are written in the caller's transaction. Edits and dependency changes are allowed in `EDITABLE_STATUSES` (`proposed`, `todo`). |
| `src/machines/` | Claude accounts (`accounts.ts`), with their day (`account-day.ts`: today's runs, working time and estimate, each run on the day it started) and their windows and days in the Orchestrator's time zone (`schedule.ts`, on `Intl`, daylight saving included; the time zone itself in `src/settings/time-zone.ts`, UTC until saved), machines and enrollment (`routes.ts`), the API view of a row, machine state label and capability sources (`model.ts`), enrollment codes and machine tokens, stored as SHA-256 hashes only (`credentials.ts`). A code is marked used in the transaction that sets the token, under the machine's row lock, so it enrolls one daemon only; wrong codes are throttled per address with the login throttle (`src/auth/throttle.ts`, key `enrollment:<address>`). |
| `src/machines/gateway.ts` | The daemon gateway (05, section 3.2; ADR 0025): the `/daemon` WebSocket, authenticated by the machine token before it opens; `hello`/`welcome` with the protocol check; the machine's reported versions, capabilities and `doctor` results; the silence timer (no message for "Machine offline after", never below twice the connection's heartbeat interval); offline on close; a newer connection replacing an older one. Work on one machine's status runs in order (a promise chain per machine), so a close and a new `hello` never cross. Tests shorten its second (`daemonSecondMs` of `buildApp`). |
| `src/mcp/` | The MCP backend (lot 2 step K; 06). `McpBackend` (`backend.ts`) takes each `mcp.call`: the run token names the run, its ticket, project and profile (refused with `FORBIDDEN` once revoked or from another machine); the input is checked against the tool's schema and the profile's `mcp_permissions`; reading tools page or cut their output under `MCP_OUTPUT_MAX_CHARACTERS` (`output.ts`) and write no event; writing tools change only the run's own ticket, in one transaction holding the project's row lock then the run's, with their `agent` events: notes, the question (`question_asked`), proposed tickets within the run's limit, the reduced submission's checks on the daemon's worktree facts and the stored report, giving up, and the progress line shown at most once per "Progress update interval" (timers restored at start). Every text an agent reads comes from `agents/templates/`: `submit-checks.md` for `ticket_submit` (`submission-checks.ts`), `mcp-tools.md` for the other tools' refusals and notes (lot 3 step L; `tool-texts.test.ts` keeps their words). |
| `src/runs/` | Runs on the server (lot 2 step J; 07 section 3, 04 section 2, 05 sections 3.3 and 4.7). `RunService` (`service.ts`): **Run now** (eligibility, GitHub token and the account id for the commit author, the machine holding the ticket's commits or else the preferred machine of 07 section 4, the account locked and counted, the first message built from `agents/templates/` with the attempt and earlier work, the run `queued`, `run.start` sent, then `dispatched`), **Resume** (own machine only), **Stop run**, the run of a cancelled or done ticket, revocation (`machine_revoked`), the dispatch acknowledgement timers (kept as `ack_deadline`, set again at start by `restoreTimers`), and the daemon's messages: `ack`, `run.state`, `run.quota_limited`, `run.events` (masked, cut to "Longest stored log entry", one row per position), `mcp.call` (given to the MCP backend, `src/mcp/`), `git.credential_request`, the owner's **answer** (`run.input` to a live session, else `run.resume` with the answer cut to the byte budget; `machine_offline` when the machine is offline or does not confirm), and the reconciliation at `hello`. Every change takes the project's row lock, then the run's, and writes its events in that transaction; a report is handled once per message id (`daemon_messages`). The ticket's status is changed only through `applyRunAction` of `src/tickets/transitions.ts`. The run token is `ort_…`, stored as its hash and revoked when the run ends. `model.ts`: status mapping, failure reasons, the API view; `first-message.ts`: the ticket as the first message shows it; `routes.ts`: the API. An account whose `limited_until` passed is shown available at once and written back by the next Run now or Resume. |
| `src/needs-you.ts` | "Needs you" items other than GitHub problems: setup still to do (no Claude account, no enrolled machine), failed setups of active projects, and machines with an incompatible daemon, an unsupported Claude Code or a `doctor` error, or offline with active runs. |
| `src/downloads.ts` | `GET /downloads/orchestrator-daemon-<version>.tgz`: the daemon package of the server's own version, from `apps/daemon/dist/` (ADR 0026); any other version is not found. `providedDaemonBuild` reads its build, compared at each `hello` and returned by `/version`. |
| `src/secrets.ts` | Encrypted secrets (ADR 0016). |
| `src/events.ts` | `recordEvent`: every state change writes an event, in the same transaction; ticket events take the time of the change so the timeline keeps its order. `projectId` is the project the event concerns (`projectEntity` and `ticketEntity` give it; a project's setting override too); events about the owner, sessions, the GitHub connection and global settings have none. |
| `src/event-log.ts` | `GET /api/events` (Activity > Event log): newest first by (`created_at`, `id`), filters, and a cursor of the last event's time (in microseconds, as stored) and id, so events written between two pages shift nothing. The index `events_project_time` (`project_id`, `created_at`, `id`) serves the project filter and the project list's last activity, `events_entity_time` the ticket and kind filters, `events_time` the rest. Each payload is parsed with its type's schema (other fields are dropped) and GitHub or Anthropic credentials are masked, also in quoted comments. |
| `src/settings/` | Settings (04, section 8). `resolveSettings` in `store.ts` is the only way code reads a setting: the project's override, then the global value, then the default of `SETTINGS` (`packages/protocol/src/api/settings.ts`, which describes each setting once: label, description, unit, range, default, per project, version that first uses it). Values are read when needed, so a change applies without a restart. Stored in `setting_values` (null `project_id` for the global value); a setting without a row uses its default. `changeSetting` is the only way to change one: it runs one change at a time (table lock, reads not blocked) and refuses a change or reset that breaks a pair of `SETTING_ORDER` (07, section 8): never above, at least a multiple (`factor`), or strictly below (`strict`), or a pair of `SETTING_PRODUCTS` above its ceiling (the acceptance criteria budget of 03 section 3.2). `routes.ts`: Settings > Limits and project overrides; every change and reset writes `setting.changed` or `setting.reset`. |
| `src/realtime/` | The realtime stream (ADR 0029). `changes.ts`: `notifyChange` (called by `recordEvent`) and `notifyRunLog` send `pg_notify` in the caller's transaction, so only committed changes are sent; `ChangeFeed` holds `LISTEN` on one pool connection, replaces a lost one after `STREAM_RETRY_MS` and then sends `resync`. `stream.ts`: `GET /api/stream`, the session checked at each keep-alive and each `session` change, open streams ended before the server closes. |
| `src/http.ts` | Input validation with the protocol schemas and the error format (`ApiError`). |
| `src/cli.ts` | The `orchestrator` command of the image: `reset-password` (`src/reset-password.ts`). |
| `src/web.ts` | Serves the built UI, and its `index.html` for screen addresses; unknown API addresses answer `not_found` (ADR 0018). |

## Daemon

`apps/daemon/src`, run as `orchestrator-daemon` (05, section 8). Its files live in `~/.orchestrator/` (`ORCHESTRATOR_HOME` in tests and development, `paths.ts`).

| Path | Role |
|---|---|
| `cli.ts` | The commands and their exit codes: 1 for a problem the owner fixes (`UserError`, printed without a stack trace), 78 (`EXIT_REFUSED`) for a refusal that retrying cannot fix, which the systemd unit does not restart. |
| `enroll.ts`, `config.ts`, `server-url.ts` | `POST /daemon/enroll` with `node:http(s)` (for `--ca-file`); `config.json` written mode 600 by a temporary file renamed, in a folder of mode 700; plain `http://` only for `localhost`, `127.0.0.0/8` and `::1` (05, section 3.2). |
| `start.ts`, `connection.ts` | The running daemon: `ServerConnection` builds `hello` before each attempt (checks, capabilities, versions, live runs), sends a heartbeat and a WebSocket ping each interval, abandons a connection after two intervals without a pong, reconnects with the backoff constants, and stops on the refusals of 05 section 3.2. Only the current socket's events count; once welcomed, the server's other messages go to `onMessage`. Tests give it fake sockets (`socketFactory`). `start.ts` recovers the runs before connecting, passes run commands to the `RunManager` and answers each with an `ack`, resends the outbox after each `welcome`, and asks the server for Git credentials (`git.credential_request`, waiting at most the run's MCP call timeout). `ServerCalls` (`server-calls.ts`) sends the agents' tool calls (`mcp.call`) and waits for each `mcp.result` at most the MCP call timeout; while disconnected, or when the connection drops (`onDisconnected`), calls get `UNAVAILABLE` at once. |
| `runs.ts`, `run.ts` | `RunManager`: runs by id, commands handled once per message id, recovery from `runs/<id>/state.json`, a run's folder removed once it ended and every report was acknowledged. `Run`: the state machine of 05 section 4.7 driven by hooks; each `PreToolUse` checked by `permissions.ts`; the agent's tool calls from the relay sent with the run token (for `ticket_submit`, with the worktree facts read then); at each `Stop` or `StopFailure`, in order: a usage limit (`usage-limit.ts`) pauses the run and closes the session, an accepted decision tool applies (`submitted`, `gave_up`, or `waiting_human` after `ticket_ask`), a queued message is sent, else a nudge (the `run.start` text), the end after the maximum; input pasted when idle or waiting for the owner, queued otherwise, refused once the session was closed; the waiting run lifetime, after which the session is closed with the worktree kept until `run.resume`; the latest status line input kept for the usage estimate; the session start timeout, the idle timeout (paused while a tool call runs) and the working time, checked each second; the live log (transcript, inputs, warnings, masked, in batches below `DAEMON_MESSAGE_MAX_BYTES`); at the end the session closed, the branch reported, the worktree removed. `secondMs` shortens the limits in tests. |
